# Stock Signal

50銘柄まで管理し、SearXNGまたはGoogle検索、3年価格データ、LM Studioのローカル生成AIを組み合わせる株式分析アプリです。

## できること

- 初期銘柄: 東急、JAL、NTT、SoftBankを含む管理リスト
- 購入日、購入単価、株数を複数明細で登録し、平均取得単価、合計株数、含み損益、保有期間を表示
- 「買いたい価格」を入力し、現在値、3年レンジ、長期トレンド、移動平均、変動率から買値の妥当性を評価
- 3年分の価格データから、3年リターン、年率リターン、最大下落率、長期トレンドを計算
- 一括分析の結果をローカルに保存し、次に開いた時も前回の判定を自動表示
- 一括分析は裏で進み、価格確認数とLM Studioの処理中ステップを画面に表示
- 候補検索は、好業績材料、3年の目安価格、直近モメンタム、変動率、既存リストとの分散、検索材料をスコア化して最大100件まで提案
- 好みではない会社は「出さない」フラグで次回以降の候補から除外
- グラフにマウスを乗せると、その日の価格と日付を表示
- 過去1年の安値帯から、買い時になりやすかった時期を表示
- 候補スコアでは、過去1年の買い場ラインを下回る銘柄を高く評価
- 候補ごとに「事業」「割安」「買い時」「リスク」「相性」の5段階で発掘プロセスを表示
- Decisionでは、業績・決算、業種環境、株価位置、需給・流動性、配当、保有損益を注意点として確認
- 業種情報は候補検索の別タブ「業種Evidence」に保存し、メイン画面を重くしすぎない形で参照
- 米国株メニューでは、Accenture、NVIDIA、Intelを初期表示し、ドルベースの保有入力、現在値、損益、AI要約を表示
- 英語記事はLM Studioで日本語要約してEvidenceに表示
- 起動中は1時間ごとに保有分析と米国株を更新し、候補検索は1日1回だけ更新
- 標準では1単元100株、30万円くらいで買える候補を優先
- 候補は自動追加せず、「好調割安」メニューから必要な銘柄だけ追加
- SearXNGまたはGoogle Custom Search JSON APIでニュースや決算材料を検索
- LM StudioのOpenAI互換APIで、購入情報と価格傾向を踏まえて買い寄り、保有、売り寄り、要注意を判定
- 検索エンジンやLM Studioが未接続でも、価格ルール分析にフォールバック

## 必要な設定

`.env.example` を参考に、必要なら `.env` を作成します。`node server.mjs` 起動時に `.env` は自動で読み込まれます。

```bash
SEARCH_PROVIDER=searxng
SEARXNG_URL=http://127.0.0.1:8081/search
SEARXNG_ENGINES=bing
GOOGLE_API_KEY=
GOOGLE_CSE_ID=
LM_STUDIO_URL=http://127.0.0.1:1234/v1
LM_STUDIO_TIMEOUT_MS=180000
PORT=5173
HOST=127.0.0.1
```

SearXNGを使う場合は `http://127.0.0.1:8081/search` を設定します。`SEARXNG_ENGINES` は通常 `bing` のままにします。DuckDuckGo、Google CSE、Reuters、Bing News はタイムアウトや認証エラーが出やすいため、アプリ側の検索指定からは除外します。Google検索を使うには、Google Custom Search JSON APIのAPIキーとProgrammable Search Engine IDが必要です。アプリ内の「設定」メニューからも保存できます。

## ローカル起動

```bash
node server.mjs
```

ブラウザで `http://127.0.0.1:5173` を開きます。

## Docker起動

```bash
docker compose up --build
```

DockerからMac上のLM Studioへつなぐため、composeでは `http://host.docker.internal:1234/v1` を使います。起動後、Docker Desktopには `local-stock-signal` が表示されます。

## 積立の既存保有と評価額

既存保有を含む「現在の評価額」と基準日を入力すると、登録した積立で購入した口数を差し引いて開始前の口数・評価額を逆算します。今月の積立が未反映なら「評価額に基準月の積立を含む」はオフにします。開始前の評価額が分かる場合は、起点を「開始前残高」に切り替えられます。

開始前の投資元本が不明な場合、比較線は「開始時評価額＋積立」で、開始以降の運用増減を表示します。開始前元本を入力した場合は、既存保有を含む投資元本と総損益も計算します。評価額を元本として扱いません。基準価額と各月の最初の観測値を使った参考計算で、実際の約定日・売却や引出し・分配金・手数料の履歴は反映していません。

証券会社に表示された取得元本・iDeCo拠出金の総額が分かる場合は、同じ基準日の「基準日の取得元本・拠出金」を入力できます。総損益はこの元本を優先し、その後の積立分だけを加算します。開始前元本＋登録積立と合わない場合は照合差を表示し、月別記録を勝手に変更しません。積立開始月は編集欄で変更でき、最初の積立設定月と同期します。グラフの最初の点は初回月の積立後です。

楽天・SBIの積立は「口座区分」でNISAつみたて投資枠・成長投資枠・課税口座を記録できます。既存の区分未登録商品は未設定のまま、MUFG iDeCoはiDeCoとして保持します。区分変更は記録のみで、注文や既存保有のNISA移管は行いません。

2商品以上を登録すると、積立画面の「並び替え」で上下の矢印から表示順を変更できます。順番はサーバーに保存し、再読み込みやバックアップ復元後も維持します。並び替えでは商品名・口座・元本・積立設定を変更せず、編集途中の入力も保持します。

NISAを選択した商品には、今年の年額・同じ枠の全商品合計・年末予定後の残り枠・来年の年額と超過月を表示します。つみたて投資枠は年120万円、成長投資枠は年240万円（設定の年間上限が低い場合はその値）です。月ごとの変更・継続設定を反映し、成長枠には日本株の登録NISA買付額を、売却済み分も減額せず合算します。未登録購入・購入日不明の日本株・NISA適格性・生涯枠は計算外です。NISA商品を楽天とSBIで同年に設定した場合も注意を表示します。入力中の設定について保存前の枠確認も表示し、超過時に金額を自動変更することはありません。株の買付情報は軽量APIで取得し、積立画面で5分ごと・再表示時に更新します。

積立を除く運用増加額と比較元本に対する増加率（年率ではありません）を表示し、同じ運用結果のNISA・課税口座の税引後の利益・差額を比較します。全取得元本が分かる場合は全額売却時の受取目安も計算します。元本不明の場合は期間増加額を利益と仮定した比較に限定し、実際の売却税・受取額は表示しません。基準価額不足の積立月がある場合は税引後比較を停止します。課税口座はプラスの利益に20.315%（2026年の国内税率）を適用し、保有中に月次課税はしません。損益通算・繰越控除・分配金・費用・NISA適格性や生涯枠は未反映です。年間枠を超える設定のNISA税引後比較も、全額非課税を仮定した参考値に限定し、超過分に非課税を適用しません。iDeCoの運用益は非課税ですが、受取時の税金や掛金所得控除はこの比較に含めません。

税制の出典: [金融庁・NISA](https://www.fsa.go.jp/policy/nisa2/know/index.html)、[国税庁・売却益の税率](https://www.nta.go.jp/taxes/shiraberu/taxanswer/shotoku/1463.htm)、[iDeCo公式・税制](https://www.ideco-koushiki.jp/guide/good.html)。

## バックアップと復元

設定の「バックアップ」で、全データを1つの `.json.gz` ファイルにダウンロードできます。日本株・米国株・BTCの保有と売却明細、配当、積立設定、候補の学習履歴、分析・価格・財務キャッシュ、各接続設定を含みます。環境変数から読み込んだ検索・AI等の設定も書き出すので、別のインストールに同じ設定を復元できます。アプリのソース、Dockerのポート設定、バックアップ自身は含みません。

復元はファイル選択、内容確認、復元の順です。破損・チェックサム不一致・不正なファイル名は入れ替え前に拒否します。現在のデータは `data/backups/before-restore-*.json.gz` に退避し、設定画面から再ダウンロードできます。復元中に再起動された場合は、起動時に未完了の変更を戻します。バックアップにはAPIキー等が含まれるため、公開しないでください。

### Google Driveの日次保存

1. Google CloudでDrive APIを有効にし、OAuth同意画面とOAuthクライアントを作成します。Webアプリのクライアントでは、認証画面に表示されるコールバックURLを認可済みリダイレクトURIに登録します。Google OAuthのテスト公開はリフレッシュトークンが期限切れになることがあるため、継続利用時は公開状態を確認してください。
2. 設定の「バックアップ」→「Googleへの接続設定」にクライアントIDとシークレットを入力し、「Googleに接続」で認証します。コールバックは同じアプリの `/api/backup/drive/callback` です。初回認証はlocalhostまたはHTTPSから行います。LANのHTTPアドレスで運用している場合は、初回のみDockerホストからlocalhostで開くか、SSHポート転送でlocalhostに接続してください。
3. 初期保存先はアプリが作成する「Stock Signal Backups」です。権限は `drive.file` で、アプリが作成・認可されたファイルのみを操作します。既存フォルダIDを指定する場合は、そのフォルダへのアクセス権が必要です。
4. 「日次バックアップ」をオンにして保存します。初期時刻は毎日04:00（日本時間）で、時刻は変更できます。アプリ停止中には実行されず、指定時刻後に起動した場合は当日分を実行します。失敗時は30分後に再試行し、設定画面に結果を表示します。「今すぐ保存」でも同じ仕組みを試せます。同じ日の再実行は同日のファイルを更新します。

Driveの認証情報は `data/backup-config.json`、結果は `data/backup-status.json` に保存され、GitとDockerビルド対象から除外されます。Dockerの `./data:/app/data` ボリュームを維持してください。Codex側のGoogle Drive接続とは独立した設定なので、Dockerだけでも日次実行を継続できます。

Googleの仕様: [オフラインアクセスとOAuth](https://developers.google.com/identity/protocols/oauth2/web-server)、[Driveアップロード](https://developers.google.com/workspace/drive/api/guides/manage-uploads)。

## 注意

全体点検の変更内容と実測結果は [REVIEW.md](REVIEW.md) に記録しています。

このアプリは投資判断の補助ツールです。利益を保証するものではありません。「買いたい価格」の評価は、過去3年の値動きに対してその価格が高すぎないか、下落リスクを取りすぎていないかを確認するための目安です。検索エンジンが未接続の場合はWeb材料を読めないため、価格データ中心の暫定判定になります。
