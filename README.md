# Stock Signal

50銘柄まで管理し、SearXNGまたはGoogle検索、3年価格データ、LM Studioのローカル生成AIを組み合わせる株式分析アプリです。

## できること

- 初期銘柄: 東急、JAL、NTT、SoftBankを含む管理リスト
- 購入日、購入単価、株数を複数明細で登録し、平均取得単価、合計株数、含み損益、保有期間を表示
- 「買いたい価格」を入力し、現在値、3年レンジ、長期トレンド、移動平均、変動率から買値の妥当性を評価
- 3年分の価格データから、3年リターン、年率リターン、最大下落率、長期トレンドを計算
- 一括分析の結果をローカルに保存し、次に開いた時も前回の判定を自動表示
- 一括分析は裏で進み、価格確認数とLM Studioの処理中ステップを画面に表示
- 候補検索は、好業績材料、3年の目安価格、直近モメンタム、変動率、既存リストとの分散、検索材料をスコア化して最大100件まで提案
- 好みではない会社は「出さない」フラグで次回以降の候補から除外
- グラフにマウスを乗せると、その日の価格と日付を表示
- 過去1年の安値帯から、買い時になりやすかった時期を表示
- 候補スコアでは、過去1年の買い場ラインを下回る銘柄を高く評価
- 候補ごとに「事業」「割安」「買い時」「リスク」「相性」の5段階で発掘プロセスを表示
- Decisionでは、業績・決算、業種環境、株価位置、需給・流動性、配当、保有損益を注意点として確認
- 業種情報は候補検索の別タブ「業種Evidence」に保存し、メイン画面を重くしすぎない形で参照
- 米国株メニューでは、Accenture、NVIDIA、Intelを初期表示し、ドルベースの保有入力、現在値、損益、AI要約を表示
- 英語記事はLM Studioで日本語要約してEvidenceに表示
- 起動中は1時間ごとに保有分析と米国株を更新し、候補検索は1日1回だけ更新
- 標準では1単元100株、30万円くらいで買える候補を優先
- 候補は自動追加せず、「好調割安」メニューから必要な銘柄だけ追加
- SearXNGまたはGoogle Custom Search JSON APIでニュースや決算材料を検索
- LM StudioのOpenAI互換APIで、購入情報と価格傾向を踏まえて買い寄り、保有、売り寄り、要注意を判定
- 検索エンジンやLM Studioが未接続でも、価格ルール分析にフォールバック

## 必要な設定

`.env.example` を参考に、必要なら `.env` を作成します。`node server.mjs` 起動時に `.env` は自動で読み込まれます。

```bash
SEARCH_PROVIDER=searxng
SEARXNG_URL=http://127.0.0.1:8081/search
SEARXNG_ENGINES=bing
GOOGLE_API_KEY=
GOOGLE_CSE_ID=
LM_STUDIO_URL=http://127.0.0.1:1234/v1
LM_STUDIO_TIMEOUT_MS=180000
PORT=5173
HOST=127.0.0.1
```

SearXNGを使う場合は `http://127.0.0.1:8081/search` を設定します。`SEARXNG_ENGINES` は通常 `bing` のままにします。DuckDuckGo、Google CSE、Reuters、Bing News はタイムアウトや認証エラーが出やすいため、アプリ側の検索指定からは除外します。Google検索を使うには、Google Custom Search JSON APIのAPIキーとProgrammable Search Engine IDが必要です。アプリ内の「設定」メニューからも保存できます。

## ローカル起動

```bash
npm ci
node server.mjs
```

ブラウザで `http://127.0.0.1:5173` を開きます。

## Docker起動

```bash
docker compose up --build
```

DockerからMac上のLM Studioへつなぐため、composeでは `http://host.docker.internal:1234/v1` を使います。起動後、Docker Desktopには `local-stock-signal` が表示されます。

## 株価予測の信頼度

日本株のDecision、米国株、BTC/JPY、USD/JPY、EUR/JPYの3か月予測に、過去に保存した予測と実績の比較を表示します。信頼度は「予測価格が実績終値の±5%以内だった割合」であり、上昇確率でもAIの主観評価でもありません。方向一致率、平均価格誤差、価格一定を仮定した場合の誤差、10〜90%予測幅の実績捕捉率を併記し、「比較の根拠」で予測日・対象日・実績日・両方の価格・外れを確認できます。ホバーにも3か月先の信頼度と件数を表示します。

画面で表示した銘柄の予測を1日1件、最初の値で保存します。次回表示時に保存済み価格と照合し、対象日より前の価格や当日の未確定価格は使いません。休場日は7日以内の次の取引日を使用し、実績不足は未評価とします。同一銘柄・同一方式の重ならない期間だけを信頼度に使い、10件未満は少数データと表示します。導入前の予測を後付けで保存することはなく、期限到来までは「蓄積中」です。従来の過去再検証は別表示で、信頼度には混ぜません。

予測と確定済み照合結果は `data/forecast-history.json` に保持し、同日の再表示・再起動で上書きしません。一括バックアップ・Google Driveバックアップの対象に含み、GitとDockerイメージには含めません。株式分割などによる過去価格の修正は確定済み照合には遡及反映しません。

## ポートフォリオのストレス・反省会

「損益推移」の下で、日米の保有株をまとめて相関、集中度、年率変動、過去の最大下落、95%週次損失目安を確認できます。USD/JPYの想定値と株価ショックを入力すると、米国株の円換算影響と、日本株の過去週次データから推定した為替感応度を分けて試算します。為替ベータは相関であり因果効果ではありません。追加資金の候補配分は、分散・配当・3か月推移・52週位置・保有集中度による説明可能な参考順位で、期待収益最大や売買指示ではありません。LM Studioが利用可能ならBull/Bear/Judgeが反対意見を含めて評価します。

日米株の予測を保存する際、当時のAI判断・信頼度・業種・トレンド情報も以後の評価用に記録します。「AI判断の反省会」では3か月または6か月の独立した予測を実績価格と照合し、価格一定の基準誤差、方向一致、予測幅の包含率や判断別成績をLM Studioへ渡します。最低標本数を満たし、学習期間と後続期間の両方で同じ失敗傾向が確認された場合に限り、該当する判断の信頼度を最大8点抑制します。売買アクションやシステムプロンプトをAIが直接書き換えることはありません。評価履歴は `data/forecast-history.json`、反省会と検証済み補正は `data/portfolio-reflection-cache.json` と `data/decision-calibration.json` に保存し、一括バックアップ対象です。

## 積立の既存保有と評価額

既存保有を含む「現在の評価額」と基準日を入力すると、登録した積立で購入した口数を差し引いて開始前の口数・評価額を逆算します。今月の積立が未反映なら「評価額に基準月の積立を含む」はオフにします。開始前の評価額が分かる場合は、起点を「開始前残高」に切り替えられます。

開始前の投資元本が不明な場合、比較線は「開始時評価額＋積立」で、開始以降の運用増減を表示します。開始前元本を入力した場合は、既存保有を含む投資元本と総損益も計算します。評価額を元本として扱いません。基準価額と各月の最初の観測値を使った参考計算で、実際の約定日・売却や引出し・分配金・手数料の履歴は反映していません。

証券会社に表示された取得元本・iDeCo拠出金の総額が分かる場合は、同じ基準日の「基準日の取得元本・拠出金」を入力できます。総損益はこの元本を優先し、その後の積立分だけを加算します。開始前元本＋登録積立と合わない場合は照合差を表示し、月別記録を勝手に変更しません。積立開始月は編集欄で変更でき、最初の積立設定月と同期します。グラフの最初の点は初回月の積立後です。

楽天・SBIの積立は「口座区分」でNISAつみたて投資枠・成長投資枠・課税口座を記録できます。既存の区分未登録商品は未設定のまま、MUFG iDeCoはiDeCoとして保持します。区分変更は記録のみで、注文や既存保有のNISA移管は行いません。

2商品以上を登録すると、積立画面の「並び替え」で上下の矢印から表示順を変更できます。順番はサーバーに保存し、再読み込みやバックアップ復元後も維持します。並び替えでは商品名・口座・元本・積立設定を変更せず、編集途中の入力も保持します。

NISAを選択した商品には、今年の年額・同じ枠の全商品合計・年末予定後の残り枠・来年の年額と超過月を表示します。つみたて投資枠は年120万円、成長投資枠は年240万円（設定の年間上限が低い場合はその値）です。月ごとの変更・継続設定を反映し、成長枠には日本株の登録NISA買付額を、売却済み分も減額せず合算します。未登録購入・購入日不明の日本株・NISA適格性・生涯枠は計算外です。NISA商品を楽天とSBIで同年に設定した場合も注意を表示します。入力中の設定について保存前の枠確認も表示し、超過時に金額を自動変更することはありません。株の買付情報は軽量APIで取得し、積立画面で5分ごと・再表示時に更新します。

積立を除く運用増加額と比較元本に対する増加率（年率ではありません）を表示し、同じ運用結果のNISA・課税口座の税引後の利益・差額を比較します。全取得元本が分かる場合は全額売却時の受取目安も計算します。元本不明の場合は期間増加額を利益と仮定した比較に限定し、実際の売却税・受取額は表示しません。基準価額不足の積立月がある場合は税引後比較を停止します。課税口座はプラスの利益に20.315%（2026年の国内税率）を適用し、保有中に月次課税はしません。損益通算・繰越控除・分配金・費用・NISA適格性や生涯枠は未反映です。年間枠を超える設定のNISA税引後比較も、全額非課税を仮定した参考値に限定し、超過分に非課税を適用しません。MUFG iDeCoではNISA・課税口座の比較を表示せず、積立・評価額・税引前損益を表示します。

## 積立の1年予測

積立記録の下に、今後1年の週次・月末評価額予測、追加積立、入金を除いた運用増減、月別明細を表示します。既存保有を含む最新参考評価額を起点に、登録済み月別金額と継続設定を使用します。当月反映済みの積立は二重加算しません。未反映分と将来の積立は月末買付（当日が月末なら翌日）と仮定し、「現在評価額＋追加積立」の運用なし比較線を併記します。将来の税金・分配金・手数料や拠出限度による調整は含みません。

過去3年以内の連続52週の価格比率を1週ずつずらして比較し、1年後の基準価額が中央値に近い経路の値動きを点線で示します。帯は各時点の10〜90%幅で、保証される範囲や校正済み確率ではありません。26通り未満、価格欠損、古い基準価額、残高不整合では予測を保留します。基準価額取得と予測計算はキャッシュし、再表示のたびに外部取得・再計算しません。

信頼度は同じファンドの保存済み1年先基準価額と後日の公表基準価額を比較します。積立額変更の影響を除くため、評価額そのものの的中率ではありません。株式等の3か月信頼度とは別集計し、比較実績がない間は「蓄積中」です。シナリオ数を実績件数に代用しません。履歴は共通の `data/forecast-history.json` に保存され、バックアップ対象です。

税制の出典: [金融庁・NISA](https://www.fsa.go.jp/policy/nisa2/know/index.html)、[国税庁・売却益の税率](https://www.nta.go.jp/taxes/shiraberu/taxanswer/shotoku/1463.htm)、[iDeCo公式・税制](https://www.ideco-koushiki.jp/guide/good.html)。

## バックアップと復元

設定の「バックアップ」で、全データを1つの `.json.gz` ファイルにダウンロードできます。日本株・米国株・BTCの保有と売却明細、配当、積立設定、候補の学習履歴、分析・価格・財務キャッシュ、各接続設定を含みます。環境変数から読み込んだ検索・AI等の設定も書き出すので、別のインストールに同じ設定を復元できます。アプリのソース、Dockerのポート設定、バックアップ自身は含みません。

学習データは候補の勝敗・時系列検証・学習補正に加え、日米株・BTC・為替・積立の保存済み予測と実績照合結果も対象です。復元確認画面に候補学習記録数・予測件数・照合済み件数を表示します。ローカル保存とDriveアップロードは同じ全データ形式を使用し、各学習ファイルを別のインストールに復元して内容が一致することをテストしています。外部のLM Studio本体やモデルファイルは含みません。

復元はファイル選択、内容確認、復元の順です。破損・チェックサム不一致・不正なファイル名は入れ替え前に拒否します。現在のデータは `data/backups/before-restore-*.json.gz` に退避し、設定画面から再ダウンロードできます。復元中に再起動された場合は、起動時に未完了の変更を戻します。バックアップにはAPIキー等が含まれるため、公開しないでください。

### Google Driveの日次保存

1. Google CloudでDrive APIを有効にし、OAuth同意画面とOAuthクライアントを作成します。Webアプリのクライアントでは、認証画面に表示されるコールバックURLを認可済みリダイレクトURIに登録します。Google OAuthのテスト公開はリフレッシュトークンが期限切れになることがあるため、継続利用時は公開状態を確認してください。
2. 設定の「バックアップ」→「Googleへの接続設定」にクライアントIDとシークレットを入力し、「Googleに接続」で認証します。Google Cloud Consoleの認可済みリダイレクトURIには、画面に表示されるURL（例: `http://localhost:5173/api/backup/drive/callback`）を完全一致で登録してください。LANのHTTPアドレスはGoogle OAuthで使えません。同じ端末で認証する場合はlocalhostからアプリを開き、別端末から使う場合はHTTPSを設定してください。
3. 初期保存先はアプリが作成する「Stock Signal Backups」です。権限は `drive.file` で、アプリが作成・認可されたファイルのみを操作します。既存フォルダIDを指定する場合は、そのフォルダへのアクセス権が必要です。
4. 「日次バックアップ」をオンにして保存します。初期時刻は毎日04:00（日本時間）で、時刻は変更できます。アプリ停止中には実行されず、指定時刻後に起動した場合は当日分を実行します。失敗時は30分後に再試行し、設定画面に結果を表示します。「今すぐ保存」でも同じ仕組みを試せます。同じ日の再実行は同日のファイルを更新します。

Driveの認証情報は `data/backup-config.json`、結果は `data/backup-status.json` に保存され、GitとDockerビルド対象から除外されます。Dockerの `./data:/app/data` ボリュームを維持してください。Codex側のGoogle Drive接続とは独立した設定なので、Dockerだけでも日次実行を継続できます。

Googleの仕様: [オフラインアクセスとOAuth](https://developers.google.com/identity/protocols/oauth2/web-server)、[Driveアップロード](https://developers.google.com/workspace/drive/api/guides/manage-uploads)。

### Sony nasneのshare2へ日次保存

Dockerホストにnasneの外付けHDD共有 `share2` をマウントしてから、NAS用Compose設定を追加して起動します。FinderでMacにマウントした場合は通常 `/Volumes/share2` です。Dockerが別のLinuxマシンで動いている場合は、そのマシン自身に共有をマウントし、Mac上のパスではなくLinux側のマウント先を指定してください。

```sh
NAS_BACKUP_HOST_PATH="/Volumes/share2" docker compose -f docker-compose.yml -f docker-compose.nas.yml up -d --build
```

設定の「バックアップ」→「nasne share2」で「書き込みを確認」を実行し、問題がなければ日次設定を保存します。初期時刻は毎日04:00（日本時間）です。「今すぐ保存」で動作確認でき、NAS上の最新ファイルを選んで復元することもできます。日次保存はアプリ起動中に行い、失敗した場合は30分後に再試行します。nasneがスタンバイ中は書き込めないため、設定時刻にnasneが利用可能であることを確認してください。

バックアップは全データ形式の圧縮ファイル `stock-signal-YYYY-MM-DD.json.gz` で、候補の学習履歴・予測実績・各種キャッシュ・接続設定も含みます。復元は最新ファイルの検証と確認を経て実行します。接続キーを含むため、家庭内ネットワークを外部公開しないでください。Sony nasneでは通常 `share1` が内蔵HDD、`share2` が外付けHDDです。

## EDINET財務分析

設定の「財務/口座」でEDINET APIキーを登録し、分析を更新すると日本株の財務資料を取得します。初回は直近400日分の書類一覧を確認するため時間がかかります。一覧をディスクに保存して共有し、当日分は30分、過去日分は24時間再利用します。同一書類の抽出済み数値も再利用し、訂正・新規書類は取り直します。

- 有価証券報告書・半期/四半期報告書と訂正報告書を対象にし、取り下げ・不開示書類は除外します。
- XMLの企業識別子、期間、連結/単体区分、単位を読みます。任意のコンテキスト名や金額の大きさで当期を推定しません。セグメント・予想値・異通貨・重複の矛盾は混ぜません。
- 最大8期間の売上・利益・営業/投資/財務CF等と、同じ長さ・会計基準の前年同期比、営業利益率、営業CF/純利益を算出します。半期利益を2倍する年換算はしません。営業CFの継続年数は重複を除いた連続通期で数えます。
- 負債総額の未取得はゼロとしません。ネットキャッシュは現金同等物（または現預金）から有利子負債を引き、有価証券は重複防止のため加算しません。企業固有のタグ・分解された借入金など、総額を確定できない場合は未取得になります。
- AI確認には期間別数値、元の項目名・書類ID、事業リスク等の抜粋、不足・更新失敗情報を渡します。画面の「EDINET 決算比較」に指標と出典を表示します。増収増益と現金収支の裏付けは小幅加点、業績悪化は減点しますが、上昇確率や利益の保証ではありません。決算期末から550日を超える数値や更新失敗ではEDINET加点を保留します。

書類一覧・抽出結果も一括/Driveバックアップに含めます。実際のAPI接続とAI応答には運用環境のAPIキー・LM Studio接続が必要です。

### 決算資料の差分・マルチエージェント分析

日本株の銘柄詳細にある「決算資料を多角分析」から手動実行します。保存済みのEDINET書類から今回期と同じ年次/中間期区分の前回期を選び、事業リスクの追加・軽減と言い回しの変化を比較します。最新EDINET PDFをページ抽出し、保存済みTDnet開示に決算説明資料があれば、関連ページの本文とスライド画像をLM Studioへ渡してセグメント成長要因と数値を抽出します。

- PDF解析にはDocker内のPopplerを使います。コンテナを再ビルドして反映してください。PDF本体と一時画像は処理後に破棄し、結果・ページ参照のみ `data/earnings-analysis-cache.json` に保存します。この結果は一括/Drive/NASバックアップに含まれます。
- スライド画像の読み取りには画像入力に対応したLM Studioモデルが必要です。未対応の場合もテキスト資料の差分とBull/Bear/Judge分析を試み、Vision未実行と明示します。決算説明資料が最近の保存済みTDnet開示にない場合は、EDINET資料中心となりスライド分析を省略します。
- Bullは上振れ材料、Bearは反証・下振れ要因、Judgeは双方と数値をまとめます。3役は同じローカルモデルを役割分担しており、独立モデル同士の投票ではありません。Judgeスコアは根拠充足度で、上昇確率や利益保証ではありません。

仕様の参照元: [EDINET API仕様書](https://disclosure2dl.edinet-fsa.go.jp/guide/static/disclosure/download/ESE140206.pdf)、[報告書インスタンス作成ガイドライン](https://disclosure2dl.edinet-fsa.go.jp/guide/static/submit/download/ESE140112.pdf)。
